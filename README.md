# InteractEntity — Руководство разработчика диалогов

Мод для **Minecraft Forge 1.20.1**. Позволяет навешивать на любого моба полноценный диалог: реплики, ветвления, квесты, события — всё описывается в JSON-файлах, программирование не требуется.

Это руководство построено **последовательно**: каждый следующий раздел опирается на предыдущий. Если читаешь впервые — иди по порядку, не перепрыгивай.

## 1. Что такое диалог и как он работает

Диалог — это **граф из узлов**. Каждый узел — одна реплика NPC. Узлы соединены переходами:
- линейный переход (`next`) — после реплики автоматически идёт следующая,
- ветвление (`options`) — игрок выбирает один из нескольких ответов, и каждый ответ ведёт в свой узел.

В JSON-файле ты описываешь:
1. **К кому привязан диалог** — какому мобу его показывать (поле `target`).
2. **Какой узел открывается первым** (поле `entry`).
3. **Все узлы** (поле `nodes`).

Когда игрок жмёт **ПКМ** по нужному мобу:
1. Мод находит JSON, у которого `target.name` и `target.tag` совпадают с именем и тегом моба.
2. Открывается экран диалога с узлом из `entry`.
3. Игрок жмёт ПКМ → переход дальше, либо выбирает кнопку → переход по этой кнопке.
4. Когда узел не имеет ни `next`, ни `options` — это **конечный узел**, ПКМ закрывает диалог.

Ничего больше понимать пока не нужно — детали в следующих разделах.

## 2. Куда класть файлы и как перезагружать

### Папка с диалогами

После первого запуска мода в `.minecraft` появится:

```
.minecraft/
└── interactentity/
    └── dialogues/   ← сюда кладёшь JSON-файлы
```

Поддерживаются вложенные папки. **Путь к файлу относительно `dialogues/` становится ID диалога**:

| Файл | ID диалога |
|------|-----------|
| `dialogues/zombie.json` | `zombie` |
| `dialogues/story/intro.json` | `story/intro` |
| `dialogues/quests/dwarf/find_axe.json` | `quests/dwarf/find_axe` |

ID нужен для команд (`/dialogue test <id>`, `/npc spawn <id>`) и для ссылок из других диалогов (`force_dialogue`, `after_dialogue`-триггер).

### Перезагрузка

После любого изменения JSON-файла **не нужно перезапускать игру**. Введи в чат:

```
/dialogue reload
```

Если диалог тестируется и нужно сбросить весь прогресс (как будто игрок видит его впервые):

```
/dialogue reload <id>
```

Например: `/dialogue reload zombie` — перезагрузит только этот диалог и сбросит, какие узлы уже посещены.

## 3. Связывание JSON-файла с мобом в мире (target)

Это **самый важный раздел для понимания**. Как мод узнаёт, что вот этот зомби в мире — именно тот, для которого написан твой JSON?

### Как мод проверяет совпадение

Когда игрок ПКМ-ит моба, мод:
1. Берёт **имя моба** (то, что висит над головой — `CustomName`).
2. Берёт **scoreboard-теги моба** (невидимые метки, которые добавляются командой `/tag`).
3. Перебирает все загруженные JSON-файлы и ищет тот, у которого:
   - `target.name` совпадает с именем моба,
   - `target.tag` есть в списке тегов моба.

Если оба совпали — открывается диалог из этого файла. Если нет — ПКМ работает как обычно (например, открывает торговлю с жителем).

### Как это выглядит в JSON

```json
{
  "target": {
    "name": "Старый Зомби",
    "tag": "old_zombie"
  },
  "entry": "start",
  "nodes": { ... }
}
```

Здесь мы говорим: «Этот диалог запустится, если у моба имя `Старый Зомби` **и** тег `old_zombie`».

### Зачем нужны оба поля

- **`name`** — то, что видит игрок (бирка над головой). По нему легко идентифицировать NPC визуально.
- **`tag`** — внутренняя метка. Позволяет различать NPC, у которых одинаковое имя. Например, два моба с именем «Стражник», но один с тегом `castle_guard`, другой — `village_guard`. Это разные диалоги.

**Оба поля обязательны.** Без тега любой случайно переименованный наковальней зомби с именем «Старый Зомби» начал бы стучаться в твой диалог.

### Способ 1 — `/npc spawn` (самый простой, для тестирования)

Встань туда, где хочешь поставить NPC, и введи:

```
/npc spawn old_zombie
```

Где `old_zombie` — это **ID файла диалога** (а не имя или тег). Мод сам:
- посмотрит в JSON, какие там `target.name` и `target.tag`,
- создаст моба нужного типа (по умолчанию зомби, можно указать другой: `/npc spawn old_zombie minecraft:skeleton`),
- задаст ему имя и тег из JSON,
- сделает его постоянным (не деспавнится).

**Пример пошагово:**
1. Положил файл `dialogues/old_zombie.json` с `target: { name: "Старый Зомби", tag: "old_zombie" }`.
2. Ввёл в чат `/dialogue reload`.
3. Встал в подходящем месте, ввёл `/npc spawn old_zombie`.
4. Появился зомби с биркой «Старый Зомби».
5. ПКМ по нему → открылся диалог.

### Способ 2 — навесить роль на уже существующего моба

Например, у тебя есть железный голем у деревни и ты хочешь дать ему диалог.

1. Подойди к голему вплотную.
2. Введи две команды:

```
/npc tag golem_guardian
```

Эта команда найдёт ближайшего моба, поставит ему имя и тег из JSON `golem_guardian`. Всё.

Если хочешь сделать руками без `/npc tag`:

```
/tag @e[type=minecraft:iron_golem,distance=..3,limit=1,sort=nearest] add golem_guardian
/data merge entity @e[type=minecraft:iron_golem,distance=..3,limit=1,sort=nearest] {CustomName:'"Хранитель"',CustomNameVisible:1b}
```

Это эквивалентно `/npc tag`, но позволяет точно контролировать, какому мобу применить.

### Способ 3 — автоматический спавн

Мод сам создаст и привяжет NPC при наступлении условия (вход в мир, попадание в зону, прохождение другого диалога). Подробно в разделе [12. Автоспавн NPC (summon)](#12-автоспавн-npc-summon).

### Проверить, какие NPC рядом

```
/npc list
/npc list 64
```

Покажет всех мобов в радиусе с их именами и тегами. Удобно для отладки.

### Удалить ближайшего NPC

```
/npc remove
```

## 4. Узлы (nodes) — основа диалога

### Что такое узел

Узел — это **одна реплика NPC + правило, что произойдёт дальше**. Все узлы лежат в объекте `nodes`, ключ — это ID узла, по которому на него ссылаются.

```json
"nodes": {
  "start":     { ... },
  "intro":     { ... },
  "question":  { ... },
  "good_end":  { ... }
}
```

Имена узлов придумываешь сам. Главное — чтобы они были уникальны внутри одного файла и понятны тебе самому.

### Тип узла определяется автоматически

Тебе **не нужно писать `type: "linear"`**. Мод сам смотрит, какие поля есть у узла:

| Что есть в узле | Тип |
|------------------|-----|
| Есть `next`, нет `options` | **Линейный** |
| Есть `options` | **Узел с выбором** |
| Нет ни `next`, ни `options` | **Конечный** |

### Тип 1 — Линейный узел

```json
"intro": {
  "text": "&fЯ давно тебя жду...",
  "next": "question"
}
```

**Как это работает:**
1. Игрок видит фразу «Я давно тебя жду...».
2. Жмёт **ПКМ**.
3. Открывается узел `question`.

Это просто «следующая реплика по нажатию».

### Тип 2 — Узел с выбором

```json
"question": {
  "text": "&fТы поможешь мне?",
  "options": [
    { "text": "&aДа!",  "next": "accept" },
    { "text": "&cНет",  "next": "refuse" }
  ]
}
```

**Как это работает:**
1. Игрок видит фразу «Ты поможешь мне?».
2. После реплики появляются кнопки: «Да!» и «Нет».
3. Игрок жмёт ПКМ или выбирает кнопку (мышью / клавишами 1–5 / стрелками + Enter).
4. Если выбрал «Да!» → откроется узел `accept`. Если «Нет» → `refuse`.

### Тип 3 — Конечный узел

```json
"end": {
  "text": "&7*Зомби замолкает*"
}
```

**Как это работает:**
1. Игрок видит реплику.
2. Жмёт ПКМ → диалог закрывается.

Конечный узел нужен, чтобы корректно завершить разговор. Без него после последней реплики нечего открывать.

### Полный список полей узла

| Поле | Тип | Что делает |
|------|-----|-----------|
| `text` | строка | Реплика NPC |
| `random_text` | массив строк | Случайная реплика из списка (вместо `text`) |
| `next` | строка | ID следующего узла (для линейного типа) |
| `options` | массив | Варианты ответа (для узла с выбором) |
| `actions` | массив | Действия, которые срабатывают **при входе** в узел |
| `auto_next_ticks` | число | Через сколько тиков автоматически перейти на `next` без нажатия ПКМ |

### Случайный текст

Если хочется, чтобы реплика звучала по-разному при каждом разговоре:

```json
"start": {
  "random_text": [
    "&7*Зомби медленно поворачивается...*",
    "&7*Зомби смотрит на тебя пустым взглядом...*",
    "&7*Зомби глухо стонет...*"
  ],
  "next": "intro"
}
```

При каждом открытии узла мод выбирает случайную строку. Если указать и `text`, и `random_text` — приоритет у `random_text`.

### Автопереход

```json
"intro": {
  "text": "&7*Долгая пауза...*",
  "next": "real_intro",
  "auto_next_ticks": 40
}
```

Через `40` тиков (≈ 2 секунды) узел сам перейдёт в `real_intro` без нажатия ПКМ. Полезно для драматичных пауз. Работает **только** в линейных узлах (где есть `next` и нет `options`).

### Минимальный рабочий пример

```json
{
  "target": { "name": "Дед", "tag": "old_man" },
  "entry": "hello",
  "nodes": {
    "hello":   { "text": "&fПривет, путник.", "next": "ask" },
    "ask":     { "text": "&fКак тебя зовут?", "options": [
      { "text": "&aСтив",   "next": "steve" },
      { "text": "&aАлекс",  "next": "alex" }
    ]},
    "steve":   { "text": "&fРад знакомству, Стив." },
    "alex":    { "text": "&fРад знакомству, Алекс." }
  }
}
```

Этого достаточно, чтобы всё заработало: 4 узла, ветвление, два конечных узла.

## 5. Форматирование текста

Текст можно красить и стилизовать **везде**: реплики, варианты ответа, имена, описания квестов.

### Цветовые коды (Minecraft-стандарт)

| Код | Цвет | Код | Цвет |
|-----|------|-----|------|
| `&0` | Чёрный | `&8` | Тёмно-серый |
| `&1` | Тёмно-синий | `&9` | Синий |
| `&2` | Тёмно-зелёный | `&a` | Зелёный |
| `&3` | Тёмно-голубой | `&b` | Голубой |
| `&4` | Тёмно-красный | `&c` | Красный |
| `&5` | Тёмно-фиолетовый | `&d` | Розовый |
| `&6` | Золотой | `&e` | Жёлтый |
| `&7` | Серый | `&f` | Белый |

### Стили

| Код | Эффект |
|-----|--------|
| `&l` | **Жирный** |
| `&o` | *Курсив* |
| `&n` | Подчёркнутый |
| `&m` | ~~Зачёркнутый~~ |
| `&k` | Обфускация (мерцающие символы) |
| `&r` | Сброс всего форматирования |

### HEX-цвета (любой оттенок)

Если стандартных 16 цветов мало:

```
&#FF6600  →  оранжевый
&#00AAFF  →  голубой
&#7F00FF  →  фиолетовый
```

### Примеры

```json
"text": "&6[&eЗомби&6] &fЯ был... &cчеловеком... &7когда-то..."
```
Получится: золотая скобка, жёлтое слово «Зомби», золотая скобка, белый текст, красное «человеком», серое окончание.

```json
"display_name": "&4[&cВраг&4]"
```

```json
"text": "&#FF6600&lОгненное приветствие!"
```
Оранжевый жирный текст.

## 6. Варианты ответа (options)

Вариант ответа — это одна кнопка в узле с выбором. У неё четыре поля:

| Поле | Тип | Описание |
|------|-----|----------|
| `text` | строка | Что написано на кнопке |
| `next` | строка / `null` | Куда ведёт этот ответ. Если `null` или отсутствует — диалог закроется |
| `condition` | объект | Условие. Если не выполнено — кнопка **не показывается** |
| `actions` | массив | Действия, которые сработают **при выборе** этого варианта (до перехода на `next`) |

### Пример с условием

```json
"question": {
  "text": "&fУ тебя есть ключ?",
  "options": [
    {
      "text": "&aДа, вот он",
      "next": "give_key",
      "condition": { "type": "has_item", "item": "minecraft:tripwire_hook" }
    },
    {
      "text": "&7Нет, ещё не нашёл",
      "next": "wait"
    }
  ]
}
```

**Как это работает:**
1. NPC спрашивает: «У тебя есть ключ?».
2. Мод проверяет условия каждой кнопки **на текущий момент**:
   - У игрока есть `tripwire_hook`? Да → показать «Да, вот он».
   - У игрока нет крючка? Кнопка скрыта.
3. Кнопка «Нет, ещё не нашёл» показывается всегда (нет `condition`).
4. Игрок видит **только те кнопки**, чьи условия выполнились.

Если все кнопки скрыты — узел ведёт себя как конечный (ПКМ закроет диалог).

### Пример с действиями при выборе

```json
"options": [
  {
    "text": "&aОтдать яблоко",
    "next": "thanks",
    "actions": [
      { "type": "remove_item", "item": "minecraft:apple", "count": 1 }
    ]
  },
  {
    "text": "&cНе отдам",
    "next": "angry"
  }
]
```

**Что произойдёт, если игрок выберет «Отдать яблоко»:**
1. Из инвентаря пропадёт 1 яблоко.
2. Откроется узел `thanks`.

Действия из `actions` варианта срабатывают **до** перехода на `next`.

## 7. Действия (actions)

Действия — это «эффекты», которые мод производит при входе в узел или при выборе варианта.

Поле `actions` — массив. Действия выполняются **по порядку, сверху вниз**.

```json
"actions": [
  { "type": "play_sound", "sound": "minecraft:entity.experience_orb.pickup" },
  { "type": "give_item",  "item":  "minecraft:diamond", "count": 3 },
  { "type": "spawn_particles", "particle": "minecraft:heart", "count": 20, "target": "entity" }
]
```

Игрок выбирает соответствующий вариант → услышит звук, получит 3 алмаза, увидит частицы-сердечки на NPC.

Ниже — все доступные действия с разбором.

---

### 7.1. `give_item` — выдать предмет игроку

```json
{ "type": "give_item", "item": "minecraft:diamond", "count": 1 }
```

| Поле | Описание |
|------|----------|
| `item` | ID предмета (`minecraft:bread`, `minecraft:netherite_sword`, ID из любого мода) |
| `count` | Сколько штук (по умолчанию 1) |

**Сценарий:** игрок согласился помочь → `actions: [{ "type": "give_item", "item": "minecraft:iron_pickaxe" }]` → у игрока в инвентаре появилась железная кирка. Если инвентарь полон — предмет выпадет под ноги.

---

### 7.2. `remove_item` — забрать предмет у игрока

```json
{ "type": "remove_item", "item": "minecraft:golden_apple", "count": 1 }
```

**Сценарий:** игрок выбирает «Отдать яблоко» → у него из инвентаря исчезает 1 золотое яблоко → переход на узел благодарности.

⚠️ Перед `remove_item` обычно стоит проверять `has_item` в `condition` варианта, иначе игрок «отдаст» предмет, которого у него нет (ничего не произойдёт, но логика будет странной).

---

### 7.3. `run_command` — выполнить команду от сервера

```json
{ "type": "run_command", "command": "say Привет от зомби!" }
{ "type": "run_command", "command": "effect give @s minecraft:glowing 60 0" }
```

Команда выполняется с **правами оператора (level 2)**. Внутри:
- `@s` — игрок, который ведёт диалог.
- `@e[...]` — обычные селекторы.

**Сценарий:** в узле `actions: [{ "type": "run_command", "command": "summon minecraft:lightning_bolt ~ ~ ~" }]` → когда игрок переходит на этот узел, у него над головой бьёт молния (без урона, если стоять не на мобе).

Через `run_command` можно делать **что угодно**: давать опыт (`xp add @s 100`), менять gamemode, открывать структуры — всё, что умеет Minecraft.

---

### 7.4. `teleport` — телепортировать игрока

```json
{ "type": "teleport", "x": 100, "y": 64, "z": -200 }
{ "type": "teleport", "x": 0, "y": 10, "z": 0, "mode": "relative" }
```

| Поле | Описание |
|------|----------|
| `x`, `y`, `z` | Координаты |
| `yaw`, `pitch` | Поворот (опционально) |
| `mode` | `"absolute"` (по умолчанию) или `"relative"` (относительно текущей позиции) |

**Сценарий:** NPC говорит «Закрой глаза...» → `actions: [{ "type": "teleport", "x": 1500, "y": 70, "z": 1500 }]` → игрока мгновенно перенесёт в точку 1500/70/1500.

С `relative` удобно делать «отскок назад»: `{ "x": 0, "y": 0, "z": -3, "mode": "relative" }` сдвинет игрока на 3 блока на север.

### 7.5. `play_sound` — воспроизвести звук

```json
{
  "type": "play_sound",
  "sound": "minecraft:entity.zombie.ambient",
  "volume": 1.0,
  "pitch": 1.0,
  "target": "player"
}
```

| Поле | Описание |
|------|----------|
| `sound` | ID звука (см. список звуков Minecraft) |
| `volume` | Громкость 0.0–10.0 (по умолчанию 1.0) |
| `pitch` | Высота 0.5–2.0 (по умолчанию 1.0) |
| `target` | `"player"` (звучит у игрока) или `"entity"` (звучит у NPC) |

**Сценарий:** при входе в узел грустной концовки → `play_sound` с `minecraft:music_disc.cat` → играет грустная пластинка.

---

### 7.6. `give_effect` — наложить эффект зелья

```json
{
  "type": "give_effect",
  "effect": "minecraft:regeneration",
  "duration": 200,
  "amplifier": 1,
  "ambient": false,
  "particles": true,
  "target": "player"
}
```

| Поле | Описание |
|------|----------|
| `effect` | ID эффекта (`minecraft:speed`, `minecraft:strength`...) |
| `duration` | Длительность в **тиках** (200 тиков = 10 секунд) |
| `amplifier` | Уровень: 0 = I, 1 = II, 2 = III, ... |
| `ambient` | `true` — частицы из маяка (тонкие). `false` — обычные |
| `particles` | Показывать частицы вообще |
| `target` | `"player"` или `"entity"` (на NPC) |

**Сценарий:** жрец благословляет игрока → `give_effect` с `minecraft:regeneration II` на 30 секунд → игрок 30 секунд получает регенерацию II уровня.

---

### 7.7. `remove_effect` — снять эффект

```json
{ "type": "remove_effect", "effect": "minecraft:poison" }
{ "type": "remove_effect" }
```

Без поля `effect` — снимает **все** эффекты. С `effect` — только указанный. `target` работает так же, как у `give_effect`.

**Сценарий:** «Лекарь снимает с тебя проклятие» → `remove_effect` без указания эффекта → у игрока пропадают все негативные (и позитивные!) эффекты.

```json
}
```

| `count` | Сколько частиц спавнить |

**Сценарий:** игрок принёс золотое яблоко → `spawn_particles` с `heart` на NPC → над зомби взлетают сердечки.

### 7.9. `camera_shake` — потрясти камеру игрока

```json
{ "type": "camera_shake", "intensity": 1.0, "duration": 20 }
```

| Поле | Описание |
|------|----------|
| `intensity` | Сила (0.5 — лёгкая, 1.5 — сильная) |

| `"night"` | 13000 |

**Сценарий:** маг творит заклинание → `set_time` со значением `night` → весь мир мгновенно перешёл на ночь.

### 7.11. `set_weather` — поменять погоду

### 7.12. `set_var` — записать переменную

```json
{ "type": "set_var", "name": "trust",  "value": "1" }
{ "type": "set_var", "name": "kills",  "op": "inc",  "value": "1" }
{ "type": "set_var", "name": "score",  "op": "dec",  "value": "5" }
```

| Поле | Описание |
|------|----------|
| `name` | Имя переменной (придумываешь сам) |
| `value` | Значение (всегда строка, можно `"15"`, `"true"`, `"hello"`) |
| `op` | `"set"` (по умолчанию), `"inc"` (прибавить), `"dec"` (вычесть) |

Подробно про переменные — в [разделе 9](#9-переменные).

### 7.13. `force_dialogue` — принудительно начать другой диалог

```json
{
  "type": "force_dialogue",
  "dialogue_id": "chapter2_intro",
  "start_node": "greeting",
  "target_tag": "guide_npc",
  "radius": 32.0
}
```

| Поле | Описание |
|------|----------|
| `dialogue_id` | ID диалога, который надо открыть |
| `start_node` | С какого узла начать (по умолчанию — `entry` целевого диалога) |
| `target_tag` | Тег моба, с которым «продолжить» (по умолчанию — текущий собеседник) |
| `radius` | В каком радиусе искать моба с этим тегом (по умолчанию 32) |

**Сценарий:** игрок нажал «Идём в подвал» → текущий диалог обрывается → ищется моб с тегом `cellar_keeper` в радиусе 32 → с ним открывается диалог `cellar_quest` с узла `door_check`.

Удобно для **сюжетных переключений**, когда один NPC «передаёт» игрока другому.

---

### 7.14. `summon_npc` — заспавнить NPC прямо во время диалога

```json
{
  "type": "summon_npc",
  "entity": "minecraft:villager",
  "name": "Торговец",
  "tags": ["trader"],
  "start_dialogue": "trader_intro",
  "despawn": true,
  "walk_away": false
}
```

| Поле | Описание |
|------|----------|
| `entity` | Тип моба (`minecraft:zombie`, `minecraft:villager`, ...) |
| `name` | Имя нового моба |
| `tags` | Массив тегов |
| `start_dialogue` | ID диалога, с которым **сразу же** начнётся разговор с этим новым NPC (текущий завершится) |
| `despawn` | Если `true` — после диалога новый NPC исчезнет |
| `walk_away` | Перед исчезновением отойдёт в сторону |

Моб появляется **за спиной игрока**.

**Сценарий:** игрок согласился на встречу → вызывается `summon_npc` → за спиной появляется новый моб → текущий диалог сразу закрывается, открывается новый разговор с заспавненным NPC.

### 7.15. `notify_npc` — пометить NPC «уведомлением»

```json
{ "type": "notify_npc", "dialogue_id": "old_zombie" }
```

Над NPC, привязанным к указанному диалогу, появится **золотистый восклицательный знак** (как в RPG, когда у NPC есть новость). Уведомление снимается автоматически, когда игрок начнёт с этим NPC разговор.

**Сценарий:** игрок завершил квест у одного NPC → в actions финального узла стоит `notify_npc` с `dialogue_id: "village_elder"` → у деревенского старосты появляется маркер «!» — игрок понимает, что у него есть что рассказать.

Кратко: `start_quest` / `update_quest` / `complete_quest` / `fail_quest`. Подробно — в [разделе 10](#10-квесты).

## 8. Условия (conditions)

Условие — это проверка факта. Используется:
- в `condition` варианта ответа — кнопка появляется/скрывается;
- в `on_revisit.conditions` — выбор, что говорить при повторном визите.

Условие проверяется **в момент показа узла** (или каждой кнопки).

---

### 8.1. `has_item` — есть предмет

```json
{ "type": "has_item", "item": "minecraft:golden_apple", "count": 1 }
```

Истина, если у игрока в инвентаре есть нужный предмет в нужном количестве.

**Сценарий:** показать кнопку «Отдать яблоко» только если оно есть.

---

### 8.2. `has_effect` — есть эффект

```json
{ "type": "has_effect", "effect": "minecraft:invisibility" }
```

**Сценарий:** скрытая кнопка «Подкрасться сзади», доступная только если игрок выпил зелье невидимости.

---

### 8.3. `health_below` — здоровье ниже значения

```json
{ "type": "health_below", "value": 10 }
{ "type": "health_below", "value": 50, "percent": true }
```

С `percent: true` — значение в процентах (от 0 до 100). Без — в HP (от 0 до 20).

**Сценарий:** реплика «Ты весь в крови...» доступна только когда у игрока меньше половины HP.

---

### 8.4. `hunger_below` — голод ниже

```json
{ "type": "hunger_below", "value": 6 }
```

От 0 до 20 (не процент).

---

### 8.5. `time_of_day` — время суток

```json
{ "type": "time_of_day", "period": "night" }
```

| Период | Тиков |
|--------|-------|
| `"day"` | 0 – 12000 |
| `"dusk"` | 12000 – 13000 |
| `"night"` | 13000 – 23000 |
| `"dawn"` | 23000 – 1000 |

---

### 8.6. `weather` — погода

```json
{ "type": "weather", "weather": "rain" }
```

`"clear"` / `"rain"` / `"thunder"`.

---

### 8.7. `dimension` — измерение

```json
{ "type": "dimension", "dimension": "minecraft:the_nether" }
```

---

### 8.8. `biome` — биом

```json
{ "type": "biome", "biome": "minecraft:desert" }
```

---

### 8.9. `visited_node` — посещал ли узел

```json
{ "type": "visited_node", "dialogue": "chapter1_intro", "node": "helped" }
```

Истина, если **кто-то на сервере** уже доходил до узла `helped` в диалоге `chapter1_intro`.

**Сценарий:** в диалоге у дочери NPC проверять, что игрок уже разговаривал с её отцом и узел `father_request` пройден.

---

### 8.10. `killed_mob` — убито мобов

```json
{ "type": "killed_mob", "entity": "minecraft:zombie", "count": 5 }
```

Истина, если **на всём сервере** убито хотя бы `count` мобов указанного типа.

**Сценарий:** скрытая ветка диалога: «Ты убивал моих сородичей...» — открывается, если игроки убили хотя бы 5 зомби.

---

### 8.11. `if_var` — значение переменной

```json
{ "type": "if_var", "name": "trust", "op": "eq",  "value": "1" }
{ "type": "if_var", "name": "kills", "op": "gte", "value": "10" }
{ "type": "if_var", "name": "chapter", "op": "exists" }
```

| Оператор | Что значит |
|----------|-----------|
| `"eq"` | Равно (как строка) |
| `"neq"` | Не равно |
| `"gt"` | Больше (число) |
| `"lt"` | Меньше (число) |
| `"gte"` | Больше или равно |
| `"lte"` | Меньше или равно |
| `"exists"` | Переменная вообще есть и не пустая |

Подробнее — в [разделе 9](#9-переменные).

---

### 8.12. `quest_status` — статус квеста

```json
{ "type": "quest_status", "quest_id": "cure_zombie", "status": "active" }
```

Статусы: `"active"`, `"completed"`, `"failed"`, `"none"` (квеста ещё нет).

**Сценарий:** реплика «Ну как, нашёл яблоко?» доступна только если квест `cure_zombie` в статусе `active`.

## 9. Переменные

Переменные — это **строковые значения, общие для всего сервера**. Они хранятся между сессиями (после выхода/входа сохраняются). Главное применение: запоминать выборы игроков и состояние сюжета.

### Где живут переменные

Переменные **общие для всего мира** (savedata уровня). Если один игрок поставил `met_bob = true`, то **все остальные игроки** увидят это значение. Это сделано, чтобы можно было строить совместный сюжет.

### Тип данных — всегда строка

```json
{ "type": "set_var", "name": "trust", "value": "1" }
```

Внутри хранится строка `"1"`. Когда нужно сравнивать как число (`gt`, `lt`, `gte`, `lte`) — мод сам распарсит строку в число. Для `eq`/`neq` сравнение идёт как строки.

### Запись: `set_var`

#### Установить значение

```json
{ "type": "set_var", "name": "chapter", "value": "2" }
```

Перезатирает старое. Раньше было `chapter = "1"` → стало `chapter = "2"`.

#### Прибавить (`inc`)

```json
{ "type": "set_var", "name": "kills", "op": "inc", "value": "1" }
```

Если `kills` была `"4"` — станет `"5"`. Если переменной не было — станет `"1"`.

`value` можно опустить — тогда `+1`:

```json
{ "type": "set_var", "name": "kills", "op": "inc" }
```

Можно прибавлять и больше единицы:

```json
{ "type": "set_var", "name": "score", "op": "inc", "value": "10" }
```

#### Вычесть (`dec`)

```json
{ "type": "set_var", "name": "lives", "op": "dec", "value": "1" }
```

Аналогично `inc`, но в минус.

### Проверка: `if_var`

#### Точное совпадение

```json
{ "type": "if_var", "name": "chapter", "op": "eq", "value": "2" }
```

Истина, если `chapter` равен строке `"2"`.

#### Сравнение чисел

```json
{ "type": "if_var", "name": "kills", "op": "gte", "value": "10" }
```

Истина, если `kills` ≥ 10. Используется только для числовых переменных.

#### Существование

```json
{ "type": "if_var", "name": "met_bob", "op": "exists" }
```

Истина, если переменная вообще когда-либо устанавливалась и не пуста.

### Сценарий: «помнить выбор игрока»

**Файл `village_elder.json`:**

```json
"first_meeting": {
  "text": "&fПривет, незнакомец! Как тебя зовут?",
  "options": [
    {
      "text": "&aСтив",
      "next": "named_steve",
      "actions": [{ "type": "set_var", "name": "player_name", "value": "Стив" }]
    },
    {
      "text": "&aАлекс",
      "next": "named_alex",
      "actions": [{ "type": "set_var", "name": "player_name", "value": "Алекс" }]
    }
  ]
}
```

В **другом** диалоге, у другого NPC:

```json
"greet_steve": {
  "text": "&fА, ты тот самый Стив, о котором говорил староста?",
  "condition": { "type": "if_var", "name": "player_name", "op": "eq", "value": "Стив" }
}
```

Что произойдёт:
1. Игрок назвался «Стив» у старосты → переменная `player_name = "Стив"`.
2. Игрок пришёл к другому NPC → реплика, привязанная к условию, появится только у того, кого «зовут» Стив.

### Сценарий: «счётчик действий»

```json
"trade": {
  "text": "&fХочешь обменять железо на изумруд?",
  "options": [
    {
      "text": "&aДавай",
      "next": "done",
      "actions": [
        { "type": "remove_item", "item": "minecraft:iron_ingot", "count": 1 },
        { "type": "give_item",   "item": "minecraft:emerald",    "count": 1 },
        { "type": "set_var",     "name": "trades_done", "op": "inc" }
      ]
    }
  ]
}
```

Через 5 успешных обменов:

```json
"loyal_customer": {
  "text": "&6Ты мой постоянный клиент! Держи скидку.",
  "condition": { "type": "if_var", "name": "trades_done", "op": "gte", "value": "5" },
  "actions": [{ "type": "give_item", "item": "minecraft:emerald", "count": 3 }]
}
```

### Сценарий: «сюжетный флаг»

В первой главе, в финальном узле:

```json
"chapter1_finale": {
  "text": "&eТы спас деревню!",
  "actions": [{ "type": "set_var", "name": "chapter", "value": "2" }]
}
```

Во второй главе, новый NPC отвечает только если первая пройдена:

```json
"options": [
  {
    "text": "&6[Я герой первой главы]",
    "next": "respect",
    "condition": { "type": "if_var", "name": "chapter", "op": "gte", "value": "2" }
  }
]
```

### Просмотр и сброс переменных

Переменные хранятся в `world/data/interactentity_dialogue.dat`. Для тестирования удобнее всего использовать `/dialogue reload <id>` — он сбрасывает прогресс конкретного диалога, но **переменные не сбрасывает**. Чтобы сбросить переменные — придётся редактировать данные мира или временно занулять их через `set_var` в тестовом узле.

## 10. Квесты

Квест — это сущность с заголовком, описанием, списком целей и (опционально) отслеживаемым предметом. Квесты отображаются в HUD и в журнале (клавиша **J**).

### `start_quest` — начать квест

```json
{
  "type": "start_quest",
  "quest": {
    "id": "cure_zombie",
    "title": "&6Лечение зомби",
    "description": "&fПомоги старому зомби найти лекарство",
    "objectives": [
      "&7[ ] Найти золотое яблоко",
      "&7[ ] Вернуться к зомби"
    ],
    "required_item": {
      "id": "minecraft:golden_apple",
      "count": 1
    }
  }
}
```

| Поле | Описание |
|------|----------|
| `id` | Уникальный ID квеста (используется в `complete_quest`, `quest_status`) |
| `title` | Заголовок (поддерживает цветовые коды) |
| `description` | Описание |
| `objectives` | Массив строк — целей. Сами по себе они не отслеживаются, ты обновляешь их через `update_quest` |
| `required_item` | Если указан — мод сам отметит первую цель как выполненную, когда у игрока появится этот предмет |

**Сценарий:**
1. NPC говорит «Принеси мне яблоко» → `start_quest`.
2. В правом верхнем углу появляется HUD с заголовком и целями.
3. Игрок поднимает с земли золотое яблоко → так как `required_item` совпал, первая цель `[ ] Найти золотое яблоко` автоматически становится `[✔] Найти золотое яблоко`.

### `update_quest` — обновить цели

```json
{
  "type": "update_quest",
  "quest_id": "cure_zombie",
  "objectives": [
    "&a[✔] Найти золотое яблоко",
    "&a[✔] Вернуться к Старому Зомби"
  ]
}
```

Перезаписывает массив целей. Удобно вручную помечать прогресс.

### `complete_quest` / `fail_quest`

```json
{ "type": "complete_quest", "quest_id": "cure_zombie" }
{ "type": "fail_quest",     "quest_id": "cure_zombie" }
```

Меняет статус. Завершённые/проваленные квесты уходят из HUD, но остаются в журнале.

### HUD-трекер

- В правом верхнем углу **до 3 активных квестов** одновременно.
- **K** — скрыть/показать трекер.
- **J** — открыть журнал (вкладки «Диалоги» / «Квесты»).

## 11. Повторный разговор (on_revisit)

Когда игрок дошёл до конечного узла, диалог считается **завершённым**. Если он снова жмёт ПКМ по тому же NPC — запускается логика `on_revisit`.

```json
"on_revisit": {
  "default": "&7*Зомби молча смотрит на тебя*",
  "default_start_node": "idle_chat",
  "conditions": [
    {
      "condition": { "type": "quest_status", "quest_id": "cure_zombie", "status": "active" },
      "text": "&fТы уже принёс яблоко?",
      "start_node": "check_apple"
    },
    {
      "condition": { "type": "quest_status", "quest_id": "cure_zombie", "status": "completed" },
      "text": "&aСпасибо тебе, друг..."
    }
  ]
}
```

### Алгоритм

1. Перебираем `conditions` сверху вниз.
2. **Первое сработавшее**:
   - Если у него есть `start_node` → откроется **полный диалог** с этого узла (как обычно).
   - Если `start_node` нет → покажется только короткая фраза `text` и диалог сразу завершится.
3. Если ни одно условие не подошло:
   - Если есть `default_start_node` → откроется полный диалог с этого узла.
   - Иначе если есть `default` → покажется короткая фраза.
   - Иначе ПКМ просто ничего не делает.

### Сценарий

Прошёл квест → ПКМ по зомби.
- Условие 1 (`active`) — нет, квест уже `completed`.
- Условие 2 (`completed`) — да! → показывается короткая фраза «Спасибо тебе, друг...» и диалог закрывается.

## 12. Автоспавн NPC (summon)

Блок `summon` позволяет мобу появляться **автоматически** без команды `/npc spawn` и без ручной разметки.

```json
"summon": {
  "entity": "minecraft:zombie",
  "custom_name": "Старый Зомби",
  "tags": ["old_zombie"],
  "despawn_after_dialogue": true,
  "walk_away_before_despawn": true,
  "spawn_position": "behind_player",
  "trigger": {
    "type": "on_join",
    "delay": 60
  }
}
```

| Поле | Описание |
|------|----------|
| `entity` | Тип моба |
| `custom_name` | Имя (должно совпадать с `target.name`) |
| `tags` | Теги (должны включать `target.tag`) |
| `despawn_after_dialogue` | Удалить моба после диалога |
| `walk_away_before_despawn` | Перед удалением пройдёт ~10 блоков и исчезнет с частицами |
| `spawn_position` | Сейчас поддерживается `"behind_player"` — за спиной игрока, 3 блока |
| `trigger` | Когда именно спавнить (см. ниже) |

После спавна мод сам:
- задаёт имя и теги,
- открывает диалог **без необходимости ПКМ** (если триггер сработал — сразу разговор),
- защищает от повторного спавна (если диалог уже пройден).

### Триггеры

#### `on_join` — при входе игрока в мир

```json
"trigger": { "type": "on_join", "delay": 100 }
```

Сработает один раз при первом входе игрока (если диалог ещё не пройден). `delay` — задержка в тиках после входа.

#### `after_dialogue` — после прохождения другого диалога

```json
"trigger": {
  "type": "after_dialogue",
  "dialogue_id": "chapter1_intro",
  "delay": 60
}
```

NPC появится через `delay` тиков после того, как игрок завершит диалог `chapter1_intro`. Удобно для сюжетных цепочек: «дошёл до конца главы 1 → через 3 секунды появляется новый персонаж».

#### `player_near` — игрок рядом с координатой

```json
"trigger": {
  "type": "player_near",
  "x": 100, "y": 64, "z": -200,
  "radius": 8.0
}
```

Сработает, **пока** игрок находится в радиусе.

#### `player_entered_area` — первый вход в зону

```json
"trigger": {
  "type": "player_entered_area",
  "x": 0, "y": 64, "z": 0,
  "radius": 15.0
}
```

В отличие от `player_near`, срабатывает **только в момент входа** в зону (нужно сначала выйти, потом войти заново). Не спамит спавнами, пока игрок стоит внутри.

#### `player_looking_for_seconds` — игрок смотрит на точку N секунд

```json
"trigger": {
  "type": "player_looking_for_seconds",
  "x": 50, "y": 70, "z": 50,
  "radius": 64,
  "seconds": 3
}
```

`radius` — на какой максимальной дистанции засчитывается «смотрит». `seconds` — сколько секунд непрерывного взгляда.

**Сценарий:** игрок 3 секунды смотрит на старую церковь → за спиной появляется призрак с диалогом.

#### `on_player_death` — после смерти игрока

```json
"trigger": { "type": "on_player_death", "delay": 20 }
```

Срабатывает после смерти игрока (после респавна).

### Деспавн

Если `despawn_after_dialogue: true`:
1. Дошёл до конечного узла.
2. Если `walk_away_before_despawn: true` — моб уходит ~10 блоков прочь.
3. Через 4 секунды — частицы портала и моб исчезает.

### Поле `repeatable`

В корне диалога:

```json
"repeatable": true
```

По умолчанию `false`. Если `true` — диалог можно проходить много раз: после завершения прогресс сбрасывается, и `summon`-триггеры могут срабатывать снова.

Полезно для бесконечных торговцев или повторяющихся «дейли»-NPC.

## 13. Внешний вид: аватар, фон, текстура кнопок

GUI-элементы можно полностью кастомизировать своими текстурами через ресурспак.

### Структура ресурспака

```
.minecraft/resourcepacks/MyDialoguePack/
├── pack.mcmeta
└── assets/
    └── mypack/
        └── textures/
            ├── entity/
            │   └── old_zombie.png
            └── gui/
                ├── dialogue_bg.png
                └── option_bg.png
```

После создания ресурспак нужно **включить** в `Параметры → Наборы ресурсов`.

### Аватар (портрет NPC)

```json
"avatar": "mypack:textures/entity/old_zombie.png"
```

- Текстура — стандартный скин **64×64**.
- Из неё вырезается **область головы** (8×8 пикселей).
- Идеально подходят обычные скины игрока или текстуры мобов из `minecraft:textures/entity/...`.

Если поле `avatar` не указано, мод подставляет автоматическую иконку (тип моба).

Можно также задать аватар прямо на конкретном мобе через NBT:

```
/data merge entity @e[name=МойНПС,limit=1] {DialogueAvatar:"minecraft:textures/entity/zombie/zombie.png"}
```

Это удобно, когда у тебя несколько мобов одного типа, но визуально разных.

### Фон диалога

```json
"background": "mypack:textures/gui/dialogue_bg.png"
```

Текстура **растягивается** на всю панель реплики. Если не указана — рисуется стандартный полупрозрачный тёмно-синий фон.

Рекомендации по размеру: ~256×80 px. Текстура не должна содержать важных деталей по краям, они могут быть обрезаны.

### Фон кнопок ответа

```json
"options_background": "mypack:textures/gui/option_bg.png"
```

Текстура накладывается на **каждую** кнопку выбора отдельно. Оптимальный размер: ~200×24 px.

### Как мод находит файл по строке `mypack:textures/gui/dialogue_bg.png`

Стандартный механизм Minecraft:
1. `mypack` → ищется папка `assets/mypack/`.
2. `textures/gui/dialogue_bg.png` → конкретный файл внутри неё.

Полный путь: `assets/mypack/textures/gui/dialogue_bg.png`. Имя `mypack` придумываешь сам — главное, чтобы оно совпадало с папкой и со строкой в JSON.

Можно также использовать **готовые** текстуры Minecraft, например:

```json
"avatar": "minecraft:textures/entity/zombie/zombie.png"
```

— тогда ресурспак не нужен.

## 14. Команды мода

### Диалоги

| Команда | Что делает |
|---------|-----------|
| `/dialogue reload` | Перезагрузить все JSON-файлы |
| `/dialogue reload <id>` | Перезагрузить один диалог + сбросить весь его прогресс |
| `/dialogue test <id> [node]` | Принудительно начать диалог с ближайшим мобом, опционально с конкретного узла |
| `/dialogue goto <node>` | В уже открытом диалоге перейти к узлу (для тестирования) |

### NPC

| Команда | Что делает |
|---------|-----------|
| `/npc spawn <id> [entity_type]` | Создать NPC у своих ног и привязать диалог |
| `/npc tag <id>` | Привязать диалог `<id>` к ближайшему мобу |
| `/npc remove` | Удалить ближайшего NPC |
| `/npc list [radius]` | Показать всех NPC в радиусе (по умолчанию 32) |

## 15. Полный пример диалога

Сюжетный квест с переменными, условиями, ветвлением и автоспавном.

```json
{
  "target": {
    "name": "Старый Зомби",
    "tag": "old_zombie"
  },
  "display_name": "&6[&eСтарый Зомби&6]",
  "entry": "start",

  "on_revisit": {
    "default": "&7*Зомби молча смотрит на тебя*",
    "conditions": [
      {
        "condition": { "type": "quest_status", "quest_id": "cure_zombie", "status": "active" },
        "text": "&fТы уже принёс яблоко?",
        "start_node": "check_apple"
      },
      {
        "condition": { "type": "quest_status", "quest_id": "cure_zombie", "status": "completed" },
        "text": "&aСпасибо тебе, друг..."
      }
    ]
  },

  "summon": {
    "entity": "minecraft:zombie",
    "custom_name": "Старый Зомби",
    "tags": ["old_zombie"],
    "despawn_after_dialogue": false,
    "trigger": { "type": "on_join", "delay": 100 }
  },

  "nodes": {
    "start": {
      "random_text": [
        "&7*Зомби медленно поворачивается...*",
        "&7*Зомби смотрит на тебя пустым взглядом...*"
      ],
      "next": "intro",
      "actions": [
        { "type": "play_sound", "sound": "minecraft:entity.zombie.ambient", "volume": 0.8 }
      ]
    },

    "intro": {
      "text": "&fЯ был... &cчеловеком... &7когда-то давно...",
      "next": "question"
    },

    "question": {
      "text": "&fМне очень плохо. Ты... можешь помочь?",
      "options": [
        { "text": "&aКонечно, чем могу помочь?", "next": "explain" },
        {
          "text": "&6[Я убил немало зомби]",
          "next": "killer_branch",
          "condition": { "type": "killed_mob", "entity": "minecraft:zombie", "count": 3 }
        },
        {
          "text": "&d[Ночью говорят по-другому]",
          "next": "night_branch",
          "condition": { "type": "time_of_day", "period": "night" }
        },
        { "text": "&cНет, мне не до тебя", "next": "refuse" }
      ]
    },

    "explain": {
      "text": "&fМне нужно &eзолотое яблоко&f. Говорят, оно может... &7вернуть меня...",
      "next": "offer"
    },

    "killer_branch": {
      "text": "&cТы убивал нас?! &7...Но... я не могу злиться. Я &fне такой&7, как они...",
      "next": "offer",
      "actions": [
        { "type": "set_var", "name": "trust_zombie", "value": "1" }
      ]
    },

    "night_branch": {
      "text": "&9Ночью... мы чувствуем себя &fсвободнее&9.",
      "next": "offer"
    },

    "offer": {
      "text": "&fПринесёшь мне золотое яблоко?",
      "options": [
        {
          "text": "&aДа, я найду его!",
          "next": "quest_start",
          "actions": [

              "type": "start_quest",
              "quest": {

                "objectives": [
                  "&7[ ] Найти золотое яблоко",
                  "&7[ ] Вернуться к Старому Зомби"
                ],
                "required_item": { "id": "minecraft:golden_apple", "count": 1 }
              }
            }
          ]
        },
        { "text": "&cИзвини, не могу", "next": "refuse" }
      ]
    },

    "quest_start": {
      "text": "&eСпасибо... &fЯ буду ждать тебя здесь...",
      "actions": [
        { "type": "play_sound", "sound": "minecraft:block.note_block.harp", "pitch": 1.2 }
      ]
    },

    "check_apple": {
      "text": "&fТы принёс яблоко?",
      "options": [
        {

    "give_apple": {
      "text": "&7*Зомби берёт яблоко дрожащими руками*",

        { "type": "camera_shake", "intensity": 0.6, "duration": 30 },
        { "type": "spawn_particles", "particle": "minecraft:heart", "count": 30, "target": "entity" },
        { "type": "play_sound", "sound": "minecraft:entity.player.levelup", "volume": 0.7 },
        {
          "type": "update_quest",
          "quest_id": "cure_zombie",
          "objectives": [
            "&a[✔] Найти золотое яблоко",
            "&a[✔] Вернуться к Старому Зомби"
          ]
        }
      ],
      "next": "finish"
    },

    "finish": {
      "text": "&eЯ чувствую себя... &aлучше&e... Спасибо тебе...",
      "options": [
        { "text": "&aРад помочь!", "next": "reward" },
        {
          "text": "&6[Мы теперь союзники]",
          "next": "trust_reward",
          "condition": { "type": "if_var", "name": "trust_zombie", "op": "eq", "value": "1" }
        }
      ]
    },

    "reward": {
      "text": "&fВозьми это... &7в знак благодарности...",
      "actions": [
        { "type": "complete_quest", "quest_id": "cure_zombie" },
        { "type": "give_item", "item": "minecraft:emerald", "count": 5 }
      ]
    },

    "trust_reward": {
      "text": "&6Ты понял меня... &fВозьми кое-что особенное...",
      "actions": [
        { "type": "complete_quest", "quest_id": "cure_zombie" },
        { "type": "give_item", "item": "minecraft:diamond", "count": 2 },
        { "type": "give_item", "item": "minecraft:emerald", "count": 5 }
      ]
    },

    "wait":   { "text": "&7...Я подожду..." },
    "refuse": { "text": "&7Понимаю... &fМожет, другой путник поможет мне..." }
  }
}
```

### Что здесь происходит шаг за шагом

1. **Игрок зашёл в мир** → через 5 секунд (`delay: 100`) за спиной появляется зомби с биркой «Старый Зомби».
2. **Игрок ПКМ-ит** → открывается узел `start` (случайная фраза + звук зомби).
3. **ПКМ** → `intro` → ПКМ → `question`.
4. **Появляются 4 кнопки**, но видимы только те, чьи условия выполнены: «Да», «[Я убил...]» (если убил 3+ зомби), «[Ночью...]» (если сейчас ночь), «Нет».
5. Если игрок выбрал **«[Я убил...]»** → `set_var trust_zombie = 1`. Этот флаг будет влиять на финал.
6. Любой положительный путь приводит к `offer`, где игрок принимает квест → `start_quest cure_zombie` с required_item «золотое яблоко».
7. **Игрок уходит, находит яблоко.** Как только оно появилось в инвентаре — первая цель квеста автоматически отмечается как выполненная (благодаря `required_item`).
8. **Игрок возвращается, ПКМ-ит зомби.** Диалог уже завершён → срабатывает `on_revisit`. Условие `quest_status active` сработало → открывается полный диалог с узла `check_apple`.
9. Кнопка «Да, вот оно!» появляется, потому что у игрока есть яблоко (условие `has_item`).
10. **Игрок выбирает «Да»** → `give_apple` отбирает яблоко, спавнит сердечки, играет звук, обновляет квест.
11. **Узел `finish`**. Здесь снова ветвление: «Рад помочь!» доступно всем, «[Мы теперь союзники]» — только если `trust_zombie == 1`.
12. **Награда:** обычная `reward` даёт 5 изумрудов, особая `trust_reward` — 5 изумрудов + 2 алмаза, и в обоих случаях `complete_quest`.

## 16. Управление в диалоге (клавиши)

| Клавиша | Действие |
|---------|----------|
| **ПКМ** | Следующий узел / выбрать наведённый вариант |
| **1–5** | Быстрый выбор варианта (если их не больше 5) |
| **↑ / ↓** | Перелистывать варианты при выборе |
| **Enter** | Подтвердить выбранный вариант |
| **Esc** | Закрыть диалог досрочно |
| **J** (вне диалога) | Открыть журнал диалогов и квестов |
| **K** (вне диалога) | Скрыть/показать HUD-трекер квестов |

## Прогресс на сервере

Весь прогресс **общий для всех игроков**:

- `visited_node` — истина, если хоть кто-то посещал.
- `killed_mob` — суммарное количество убийств всех игроков.
- Переменные (`set_var`/`if_var`) — общие.
- Квесты видны в журнале у всех.

Это делает возможными совместные сюжеты: один игрок открывает ветку, остальные могут её увидеть. Если хочется индивидуальный прогресс — нужно использовать `run_command` со скорборд-цели на конкретного игрока.
